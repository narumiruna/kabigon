## R1 — Unclosed ignored element consumes capture-root end tag

[Comment 3995571790](https://github.com/narumiruna/kabigon/pull/217#discussion_r3995571790); also the substantive summary of review 5185781075.

- **Severity:** P2. Wrong content from malformed HTML, not demonstrated widespread failure.
- **Evidence:** For `<main><p>Article body</p><nav>Navigation</main><aside>Outside content</aside>`, the reviewed head returns `<main><p>Article body</p><aside>Outside content</aside>`. The base also mishandles the boundary but returns only `<main><p>Article body</p><aside>`: the PR newly exposes outside text when `</main>` decrements ignored depth.
- **Scope:** In scope; worsens boundary corruption and directly contradicts the PR's subtree-containment goal.
- **Outcome:** Actionable and not yet addressed → Already addressed by this verified follow-up.
- **Fix:** Track open tag names and close through the matching ancestor, even while ignoring descendants. Unmatched end tags cannot decrement an unrelated depth.
- **Verification:** `test_capture_root_closes_unclosed_ignored_subtrees` passes for unclosed `nav`, `nav/div`, and `svg/g`. `test_nested_capture_root_inside_ignored_subtree_does_not_end_capture` preserves later article text when an ignored descendant has the capture root's tag name.

## R2 — HTTP 200 Access Denied content accepted as success

[Comment 3995579227](https://github.com/narumiruna/kabigon/pull/217#discussion_r3995579227), review 5185788343.

- **Severity:** P2, rather than the review's P1. Silent bad extraction and skipped fallbacks are reproducible for successful-status denial documents; no evidence establishes widespread or urgent impact.
- **Evidence:** A 471-character `Access Denied` document beginning `You don't have permission to access ... on this server.` is rejected by the base's marker check and accepted by the reviewed head. `CurlCffiLoader.load` validates HTTP status before calling `ensure_usable_content`; HTTP 200 cannot trigger that status error. `LoadChain.load` returns the first non-empty successful result and continues on `LoaderContentError`.
- **Contradicting evidence / constraint:** Existing `test_ensure_usable_content_accepts_error_documentation` deliberately accepts an `Access Denied` heading with troubleshooting prose. Restoring an unconditional substring or heading rejection would defeat the original PR goal.
- **Scope:** In scope; removal of the marker introduces false success. Require heading plus immediate denial diagnostics rather than rejecting mentions throughout documentation.
- **Outcome:** Actionable and not yet addressed → Already addressed by this verified follow-up.
- **Fix:** An exact, case-insensitive `Access Denied` heading plus immediate permission-denial or request-blocking diagnostic raises `LoaderContentError`; unrelated prose and headings remain accepted. This is deliberately a narrow heuristic, not a classifier for all WAF templates.
- **Verification:** Twelve plain/ATX/Setext/bold heading and diagnostic combinations pass in `test_ensure_usable_content_rejects_contextual_access_denied_pages`. `test_curl_cffi_loader_falls_back_after_http_200_access_denied` verifies successful HTTP status cannot bypass the guard and the chain returns the next loader's article. Existing short-page and error-documentation tests, plus three documentation counterexamples, pass.

## R3 — Optional end tags leave ignored-subtree depth unbalanced

[Comment 3995579229](https://github.com/narumiruna/kabigon/pull/217#discussion_r3995579229), review 5185788343.

- **Severity:** P2. Valid HTML can lose the complete article body.
- **Evidence:** For `<main><nav><ul><li>One<li>Two</ul></nav><p>Article body</p></main><aside>Outside content</aside>`, the head returns only `<main>`. The base has other extraction defects but retains `Article body`; PR counting every descendant newly suppresses that text when optional `</li>` tags are absent.
- **Scope:** In scope; directly regresses the subtree fix. Named-ancestor matching can discard unclosed descendants when the ignored ancestor closes without introducing a full HTML5 parser.
- **Outcome:** Actionable and not yet addressed → Already addressed by this verified follow-up.
- **Fix:** The same named-tag stack used for R1 removes open descendants when their ignored ancestor closes. It does not require a matching explicit end tag for every start tag.
- **Verification:** `test_ignored_descendants_do_not_extend_capture` covers omitted list, paragraph, and table-cell end tags, an unclosed `div`, unmatched closing tags, explicit nested ignored elements, and void/self-closing tags. All preserve the article body and exclude navigation/outside text.
